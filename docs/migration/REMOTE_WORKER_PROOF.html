Prueba de ContainerHub en worker remoto

Ejecutar desde el manager del Swarm.

1. Inicializar mTLS, red y secrets

cd /home/ramiro/dockerway/containerhub
packages/containerhub-agent/deploy-remote-worker-proof.sh init

2. Configurar y desplegar el backend

El backend debe ser un servicio Swarm, estar unido a containerhub-agent-network y tener los tres secrets/variables cliente descritos en packages/containerhub-agent/TLS.md, sección 5.

3. Desplegar el agent y el task de prueba

packages/containerhub-agent/deploy-remote-worker-proof.sh deploy \
  REGISTRY_ALCANZABLE_POR_DEBIANVM/containerhub-agent:VERSION \
  NOMBRE_SERVICIO_BACKEND

El script construye y publica el agent, lo despliega globalmente y crea containerhub-remote-proof en debianvm.

4. Probar

  1. Abrir Nodes: ambos nodos deben estar saludables.
  2. Abrir el task containerhub-remote-proof.
  3. Probar terminal remoto, stats y ghosts.

5. Limpiar

packages/containerhub-agent/deploy-remote-worker-proof.sh cleanup

El cleanup conserva la red, los secrets y la PKI.

Resultado 2026-09-14

  • El agent global DNSRR ejecutó una réplica en ramiro y otra en debianvm, sin puertos públicos.
  • Ambos endpoints aceptaron mTLS y rechazaron conexiones sin certificado cliente.
  • Chromium autenticado verificó Nodes, un ghost remoto real, estadísticas con cuatro gráficos y terminal remota mediante eventos físicos de teclado.
  • Los cuatro escenarios pasaron en serie; se eliminaron servicios, contenedores, imágenes, credenciales y archivos temporales.
