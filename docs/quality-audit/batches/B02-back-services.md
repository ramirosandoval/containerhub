## Hallazgos

### B02-001 — redes: sustitución destructiva — alta — comprobado en fuente, sin repro Docker
- Evidencia: `packages/containerhub-back/src/modules/services/routes/ServiceRoutes.ts:196-200` → `packages/containerhub-back/src/modules/services/services/ServiceService.ts:986-997`: `updateNetwork` inspecciona, llama **primero** a `removeNetwork` (`:995,999-1001`) y luego a `createNetwork` (`:996,982-984`); no hay rollback ni prueba específica de update. Un error al crear la red reemplazante deja la red anterior eliminada. En `:1003-1013`, `getOrCreateNetwork` también trata cualquier fallo de inspect como red ausente, en vez de limitarlo a 404.
- Impacto: la operación de editar red puede perderla si la creación posterior falla; un error de daemon/permisos en provisión intenta creación indebidamente. No se comprobó el comportamiento ante red conectada, donde Docker podría rechazar la eliminación.
- Contraste: búsqueda de `updateNetwork`/`getOrCreateNetwork` en `packages/containerhub-back/src/modules/services/**/__tests__/*.test.ts`: sin test localizado; `ServiceCreate.test.ts:39-46,71-85` sólo simula red no encontrada y alta.
- Intervención mínima: no destruir la red antes de validar que la sustitución es realizable; restringir el fallback de inspect a 404 y cubrir fallo de creación con stub.

### B02-002 — validación de límite de logs — media — comprobado por ejecución aislada
- Evidencia: `packages/containerhub-back/src/modules/services/routes/ServiceRoutes.ts:132-136,42-50,154-158` → `packages/containerhub-back/src/modules/services/services/ServiceService.ts:764-775`: `parseInt` acepta prefijos numéricos y la rama numérica no exige entero. Ejecución con `node --import tsx`: `parseTaskLogTail('12garbage')` devolvió `12`; `parseTaskLogTail(1.5)` devolvió `1.5`. El valor llega a Docker en `:862-864,887-889`.
- Impacto: peticiones malformadas obtienen una cola distinta de la solicitada o pasan valores fraccionarios a Docker; el error ya anuncia «integer», pero no lo garantiza.
- Contraste: `packages/containerhub-back/src/modules/services/services/__tests__/TaskLogs.test.ts:39-43` sólo cubre `'30'`, `'0'`, `'10001'`; no cubre sufijos ni fracciones.
- Intervención mínima: validar el string completo como entero decimal y exigir `Number.isInteger` antes del rango.

### B02-003 — decodificación de logs crudos por fragmentos — baja — comprobado por ejecución aislada
- Evidencia: `packages/containerhub-back/src/modules/services/routes/ServiceRoutes.ts:138-152` → `packages/containerhub-back/src/modules/services/services/ServiceService.ts:815-849,861-885`: en la rama sin cabecera multiplexada, cada chunk se convierte por separado con `.toString('utf8')` (`:829-832`), sin conservar bytes UTF-8 incompletos. Reproducción con bytes de `café\n` divididos dentro de `é`: el decoder emitió `caf��`.
- Impacto: caracteres multibyte de logs no multiplexados pueden quedar corruptos en el stream WebSocket si TCP parte un carácter; no se afirma frecuencia real en Docker.
- Contraste: `packages/containerhub-back/src/modules/services/services/__tests__/TaskLogs.test.ts:22-37` prueba salida raw en bloque y fragmentos multiplexados, no raw partido dentro de UTF-8.
- Intervención mínima: usar `StringDecoder` de Node o `TextDecoder` en modo stream para la rama raw; añadir un caso de fragmentación multibyte.

### B02-004 — arranque duplicado de stream WebSocket — media — probable
- Evidencia: `packages/containerhub-back/src/modules/services/routes/ServiceRoutes.ts:138-152` → `packages/containerhub-back/src/modules/services/services/ServiceService.ts:861-885`: `stopStreaming` se asigna sólo **después** de esperar `streamTaskLogs(request.params.taskId, await taskLogFilters(payload), ...)` (`:143-146`). Dos mensajes antes de completar ambos awaits pasan `if (stopStreaming) return`; cada uno puede abrir un stream, y el cierre sólo destruye la última función asignada (`:151`).
- Impacto: conexiones de logs concurrentes por socket consumen recursos; una suscripción previa puede persistir hasta cierre upstream. No se reprodujo el interleaving ni hay test de mensajes simultáneos localizado.
- Contraste: `packages/containerhub-back/src/modules/services/services/__tests__/TaskLogs.test.ts:13-43` prueba decoder/tail, `ServiceLogs.test.ts:79-120` la ruta HTTP; ninguno ejercita esta carrera WebSocket.
- Intervención mínima: reservar estado `starting` sincrónicamente antes del primer `await` y detener cualquier stream que llegue tarde tras cierre; test con dos mensajes mientras filtros están pendientes.
